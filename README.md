## Features

| Feature | Description | Reference |
|---------|-------------|-----------|
| [`bun`](src/bun/README.md) | Install the Bun JavaScript runtime. | `ghcr.io/raine-works/devcontainer-features/bun:1` |
| [`deno`](src/deno/README.md) | Install the Deno JavaScript runtime. | `ghcr.io/raine-works/devcontainer-features/deno:1` |

## Usage

Add one or more features to your `devcontainer.json`:

```json
{
    "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
    "features": {
        "ghcr.io/raine-works/devcontainer-features/bun:1": { "version": "1.2.0" },
        "ghcr.io/raine-works/devcontainer-features/deno:1": {}
    }
}
```

Omit `version` (or set it to `latest`) to get the newest release. The `:1` tag follows the feature's major version, so you get compatible updates without breaking changes.

Requirements: a Debian/Ubuntu based image. Each feature's README documents its options.

## Repository layout

```
src/<feature>/devcontainer-feature.json   Feature metadata and options
src/<feature>/install.sh                  Install script (runs as root at build time)
src/<feature>/NOTES.md                    Hand-written notes appended to the generated README
test/<feature>/scenarios.json             Scenario tests (pinned versions, base images)
test/<feature>/*.sh                       Assertions run inside each scenario
.github/workflows/                        Validate, test, and release pipelines
```

Per-feature `README.md` files are generated from `devcontainer-feature.json` on release. Edit `NOTES.md` instead of the README.

## Development

Open the repo in its dev container (it ships the `devcontainer` CLI), then:

```bash
# Autogenerated tests for one feature against a base image
devcontainer features test --skip-scenarios -f bun -i ubuntu:latest .

# Scenario tests (pinned versions)
devcontainer features test -f bun --skip-autogenerated --skip-duplicated .
```

## Releasing

1. Bump `version` in the feature's `devcontainer-feature.json`.
2. Merge to `master`.
3. Run the **Release dev container features & Generate Documentation** workflow manually. It publishes to GHCR and opens a PR with regenerated docs.

The release workflow needs a `GH_TOKEN` repository secret with permission to push branches and open PRs.
